## A. By hand: the protocol with nothing hidden

A client written with the Python standard library only (`subprocess` + `json`), speaking to the server's stdin/stdout. MCP is **JSON-RPC 2.0, one message per line**: a request has an `id` and expects a reply with the same `id`; a notification has no `id`. Three methods carry almost everything: `initialize` (handshake), `tools/list` (discovery), `tools/call` (use).

**client -> server** (handshake: who I am and what I support)
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {
    "protocolVersion": "2025-11-25",
    "capabilities": {},
    "clientInfo": {
      "name": "hand-rolled-client",
      "version": "0"
    }
  }
}
```

### Everything the server was ever asked

| method | times | what it is |
|---|---|---|
| `server/discover` | 1 | handshake (current era): who are you, what do you speak |
| `tools/list` | 1 | discovery: what tools do you have |
| `tools/call` | 2 | use one |

The agent made 3 model calls (its steps); the server saw 2 tool calls. The model's 3 decisions -- including which tool to call and the final `finalize` -- happened on the host and nothing about them crossed this wire. There is no `messages`, no `prompt`, no `system`, no `model` in any request: **the AI runs in the host**, and the server cannot tell whether a model, a script or a person is calling it. The one thing it learns about its caller is the `clientInfo.name` it chose to announce.

What the server *does* see is whatever the host puts in tool arguments. Here the agent's search query is a slice of the adjuster's notes, so a fragment of the notes did cross the wire as a `query`. Treat tool arguments as data you are sharing with the tool's operator.
